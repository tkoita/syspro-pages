1-2 プログラムは、カーネルに頼んで仕事をする

第4週目の地図で、コマンドとハードウェアの間にはカーネルがいました。ファイルを開く・読む・書く・閉じるは、どれもカーネルへの頼みごと（システムコール）です。頼むと、カーネルは必ず数で返事をします。

open開いて、番号をもらうfd = open(名前, O_RDONLY);成功すると番号。失敗すると -1。
read番号の先から読むn = read(fd, buf, 4096);読めたバイト数。終わりなら 0。
write番号の先へ書くwrite(1, buf, n);1番（画面）へ n バイト書く。
close番号を返すclose(fd);使い終わった番号を返す。

番号の 0（キーボード）・1（画面）・2（画面のエラー用）は、起動したときからもう配られています。

1-3 strace の1行の読み方

strace コマンド と打つと、そのコマンドがカーネルに頼んだことが、1回につき1行出ます。読むのは「名前」と「= の右（返事）」だけで十分です。

openat(AT_FDCWD, "memo.txt", O_RDONLY) = ○
└名前┘ └────── 頼んだ中身 ──────┘   └返事（番号）┘

○ に、カーネルがくれた番号が入ります（何番になるかは、演習Aで自分の目で見ます）。

失敗したときは、返事が -1 になり、その後ろに理由の短い名前が付きます。

openat(AT_FDCWD, "nosuch.txt", O_RDONLY) = -1 ENOENT (No such file or directory)
open は、strace では openat と出ます。今の Linux では、C の open が中で openat という頼み方をするからです（中身は同じです）。AT_FDCWD は「今いる場所から探して」という意味です。

1-4 『伽藍とバザール』：見えない失敗は、誰にも見つけられない

引用 ── 教訓 8（リーヌスの法則）ベータテスタと共同開発者の基盤さえ十分大きければ、ほとんどすべての問題はすぐに見つけだされて、その直し方もだれかにはすぐわかるはず。Raymond はこれを「目玉の数さえ十分あれば、どんなバグも深刻ではない」と言い直しています。→ ただし、目玉が何個あっても、見えないものは見つけられません。今日の mycat1 は、失敗しても何も言いません。strace は、プログラムが黙っていても、カーネルとのやりとりを見せてくれる「もう1つの目玉」です。

/* mycat1.c ---- ファイルの中身を出す : バージョン 1 */
#include <fcntl.h>      /* open               */
#include <unistd.h>     /* read, write, close */

#define BUFSIZE 4096

int main(int argc, char *argv[])
{
    char buf[BUFSIZE];
    int  fd, n;

    fd = open(argv[1], O_RDONLY);               /* ① 番号をもらう   */
    while ((n = read(fd, buf, BUFSIZE)) > 0)    /* ② その番号で読む */
        write(1, buf, n);                       /* ③ 1番に書く     */
    close(fd);                                  /* ④ 番号を返す     */
    return 0;
}

用語集

システムコール
プログラムが、カーネル（OS の中心）に仕事を頼むための窓口。open・read・write・close など。
strace
コマンドを動かしながら、そのコマンドが頼んだシステムコールと返事を1行ずつ出すコマンド。出力は2番に出る。
openat
strace で見える、open の頼み方。中身は open と同じ。
ファイルディスクリプタ
open が返す小さな番号。read・write はこの番号でファイルを指す。0・1・2 は起動したときから配られている。
-1
システムコールが失敗したときの返事。strace では、後ろに理由の短い名前が付く。
ENOENT
理由の名前の1つ。「そんなファイル（やディレクトリ）は無い」。
EBADF
理由の名前の1つ。「そんな番号（ファイルディスクリプタ）は無い」。
終わり方（終了ステータス）
プログラムが終わるときに返す数。main の return の数。0 が成功、0 以外が失敗。echo $? で見る。strace では最後の +++ exited with ○ +++ に出る。
perror
失敗の理由を、人の言葉にして2番（標準エラー出力）に書く関数。#include <stdio.h> が要る。
/dev/null
書いたものを捨てる特別なファイル。> /dev/null で1番の出力を捨てる。
