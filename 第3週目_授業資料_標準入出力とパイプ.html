1-2 差し替えているのは、シェルである

Linux標準教科書6章に出てくる > < 2> | は、すべてシェルの機能です。プログラムの機能ではありません。

コマンドライン0番1番2番
./a.out端末端末端末
./a.out > out.txt端末out.txt端末
./a.out < in.txtin.txt端末端末
./a.out 2> err.txt端末端末err.txt
./a.out | ./b.out端末パイプ端末

5つとも、a.out のソースコードは1文字も違いません。

これはUnixの弱点ではなく、設計です。プログラムがつなぎ先を知らなくていいからこそ、sort はファイルにもパイプにも端末にもつなげます。何百というコマンドが、どんな順番でもつながるのはこのためです。

そして、同じ理由で先週の more01 は壊れました。

強さと事故は、同じ設計から出てきています。どちらか片方だけを取ることはできません。

B-1　mywc01.c を読む（4分）― コンパイルはまだしない

エディタで mywc01.c を作り、下のコードを入れてください。入れたら、コンパイルの前に3問に答えてください。

/* mywc01.c ---- 行数を数える : バージョン 0.1 */
#include <stdio.h>

int main(void)
{
    int  c;
    long lines = 0;

    while ((c = getchar()) != EOF)
        if (c == '\n')
            lines++;

    printf("\033[1;36m======================\033[m\n");

人間の目には 200 に見える。機械には見えない。

B-4　カーネルに聞いてみる（5分）

これは配布されています。配布セットの whereami.c を作業ディレクトリにコピーしてください（cp ~/Downloads/whereami.c .）。今日の主役ではないので、打たずに済ませます。ただし下のコードには目を通してください。やっていることは、3本の口それぞれについて isatty と ttyname を呼んでいるだけです。

/* whereami.c ---- 自分の 0/1/2 がどこにつながっているかを聞く */
#include <stdio.h>
#include <unistd.h>

void report(int fd, const char *name)
{
    if (isatty(fd))
        fprintf(stderr, "fd %d (%s) : 端末です  -> %s\n", fd, name, ttyname(fd));
    else
        fprintf(stderr, "fd %d (%s) : 端末ではありません\n", fd, name);
}

int main(void)
{
    report(0, "標準入力      ");
    report(1, "標準出力      ");
    report(2, "標準エラー出力");
    return 0;
}
gcc -Wall -o whereami whereami.c
./whereami                 # 3本とも端末
./whereami | cat           # 1番だけ変わる
echo hi | ./whereami       # 0番だけ変わる
./whereami > log.txt        # 報告は画面に出たまま
./whereami 2> log.txt ; cat log.txt
観察して答える
① ./whereami | cat のとき、報告が画面から消えなかったのはなぜですか。
② ./whereami > log.txt のとき、log.txt の中身はどうなっていますか。
③ 端末のときに出る /dev/pts/0 のような名前。先週これに似たものを開きませんでしたか。
①の答えは「報告を2番に出しているから」です。パイプが差し替えたのは1番だけでした。
そして、いま自分が書いた fprintf(stderr, ...) と、Stage A-1 で打った 2> は、同じ「2番」の話です。C言語側とシェル側から、同じものを見ていたことになります。

/* mywc02.c ---- 行数を数える : バージョン 0.2 */
#include <stdio.h>
#include <unistd.h>              /* ★変更1：isatty を使うため */

int main(void)
{
    int  c;
    long lines = 0;

    while ((c = getchar()) != EOF)
        if (c == '\n')
            lines++;

    if (isatty(1)) {              /* ★変更2：1番の先を聞く */
        printf("\033[1;36m======================\033[m\n");
        printf("  行数 : \033[1;32m%ld\033[m 行\n", lines);
        printf("\033[1;36m======================\033[m\n");
    } else {                      /* ★変更3：機械が読むなら素のまま */
        printf("%ld\n", lines);
    }
    return 0;
}
手を動かす前に、説明する。

埋める前に「なぜ else 側は色を消すのか」を隣の人に説明してください。説明できないまま書き写した場合、あなたは今日の90分を失っています。先週と同じルールです。

今日の用語

用語意味
ファイルディスクリプタプロセスが持つ入出力の口に付いた番号。0=標準入力、1=標準出力、2=標準エラー出力。プロセスは、この番号を通してしか外の世界とやり取りできない。
標準エラー出力（2番）エラーメッセージ専用の口。1番と分かれているから、「結果はファイルへ、エラーは画面へ」ができる。C言語では fprintf(stderr, ...)。
リダイレクト番号のつなぎ先を差し替えること。>=1番、2>=2番、<=0番、>>=追記、2>&1=2番を1番と同じ場所へ。やっているのはシェル。
パイプ（|）左のコマンドの1番と、右のコマンドの0番を直結すること。プロセス間通信のいちばん基本的な形。
フィルタ「0番から読んで、1番に書く」形をしたコマンドの総称。形が同じだから、どの順番でもつながる。
isatty(fd)「この番号の先は端末ですか」とカーネルに聞く関数。端末なら1、違えば0。#include <unistd.h> が必要。
ttyname(fd)その番号がつながっている端末の名前（/dev/pts/0 など）を返す。先週の /dev/tty と同じ世界のもの。
エスケープシーケンスESC で始まる制御用の文字列。\033[1;32m で緑、\033[m で元に戻す。画面には見えないが、データとしては確かに存在する。
シェル変数N=200 のように名前に値を入れておく箱。取り出すときは $N。入るのは常に文字列で、数として扱えるかどうかは、使うときに決まる。
算術評価 $(( ))中身を数式として計算する書き方。$((3 * 2)) は 6。中身が数として読めないとエラーになる。$( ) とは別物で、括弧の数が違う。今日壊れたのはこちら。
コマンド置換 $( )コマンドの出力そのものを値として取り出す書き方。N=$(wc -l < f)。飾りが混ざっていると使えない。
シェルスクリプト打ったコマンドをファイルに並べたもの。1行目に #!/bin/bash、chmod +x で実行可能にする。$1 は1つ目の引数。
