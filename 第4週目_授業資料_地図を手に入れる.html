1-3 Linux はどこから来たか

Linux標準教科書 第1章の内容です。年号は覚えなくてかまいません。流れだけつかんでください。

1969 アメリカの研究所で Unix が生まれる。数年後に、C 言語で書き直される（この授業が C を使う理由）
1983 Unix のような仕組みを、誰でも自由に使えるソフトだけで作ろうという GNU の計画が始まる。道具（コンパイラ gcc など）は揃ったが、3段目のカーネルがなかなか完成しない
1991 フィンランドの大学生 リーナス・トーバルズ（当時21歳。『伽藍とバザール』の訳では「リーヌス」）が、趣味で作ったカーネルをインターネットに公開する。これが Linux
いま Linux カーネル ＋ GNU の道具 ＋ いろいろなソフトをまとめてインストールできるようにしたものが「ディストリビューション」（Ubuntu・AlmaLinux など）
Linux はどこで動いているか（Linux標準教科書 1.3）　Web やメールのサーバー、Android のスマートフォン、家電、IoT の機器、そして AI・機械学習のソフトの多く。AI のソフトの多くも Linux の上で動いています（1.3.5）。今日使う Copilot のような AI と Linux は、遠い話ではありません。
「Linux は地味？」　Linux標準教科書 1.1.2 にこう書かれています（要約）。1つ1つのコマンドは小さく地味で、何のために覚えるのか最初は分からない。でも、その小さな組み合わせがインターネットのような大きなシステムを形作っている。——第3週目のパイプは、まさにその「組み合わせ」でした。

1-4 伽藍とバザール

Eric S. Raymond『伽藍とバザール』（山形浩生 訳）は、なぜ Linux がこんなやり方でうまくいったのかを考えた文章です。2つの作り方を比べています。

伽藍（がらん）方式

大聖堂を建てるように、少人数の名人が、完成するまで外に見せずに静かに作る。バグは深く隠れたものだと考え、何か月もかけて調べてから出す。

バザール方式

にぎやかな市場のように、早めに・しょっちゅう公開して、大勢に使ってもらい、見つけてもらい、直してもらう。Linux はこちらで作られた。

今日は、本文の19の「教訓」のうち3つを読みます（引用は山形浩生訳から）。

引用 ── 教訓 1よいソフトはすべて、開発者の個人的な悩み解決から始まる。→ 課題3で、あなた自身の「めんどうだ」から出発します。
引用 ── 教訓 7はやめのリリース、ひんぱんなリリース。そして顧客の話をきくこと→ リーナスは、作りかけのカーネルを1日に何回も公開することさえあった。完成してから見せるのではなく、見せながら直す。
引用 ── 教訓 8（リーヌスの法則）ベータテスタと共同開発者の基盤さえ十分大きければ、ほとんどすべての問題はすぐに見つけだされて、その直し方もだれかにはすぐわかるはず。Raymond はこれを「目玉の数さえ十分あれば、どんなバグも深刻ではない」と言い直しています。→ 課題2で、あなたが「目玉」になります。

1-5 なぜ今、これを学ぶのか ― AI は「もう1つの目玉」

  1. Copilot のような AI は、インターネットに公開された大量のコードや文章から学んでいます。その多くは、まさに「バザール」で公開されてきたものです。
  2. だから AI は、あなたの横にいる「もう1つの目玉」として、とても役に立ちます。分からないコマンドの意味を、何度でも聞けます。
  3. ただし AI は、間違っていても、正しいときと同じ口調で答えます。「自信がなさそう」という合図が出ません。
  4. AI の答えが合っているかを決めるのは、地図を持っていて、自分でコマンドを打って確かめられる人です。この授業でシステムプログラミングを学ぶのは、そのためです。

課題1　カーネルに会う

必須コマンドを1つずつ打って、「地図の何段目について教えてくれたか」を考えます。1段目から4段目まで、全部の段に会えます。

やり方

  1. 下のコマンドを上から順に1つずつ打つ。
  2. 出てきたものを見て、地図の何段目のことかを予想する（15秒）。
  3. 「答え」を開いて確かめる。違っていてもかまいません。違った理由を読めば十分です。
  4. 余裕があれば分からないコマンドを1つ選び、Copilot に「○○ コマンドは何をしますか。初心者向けに2文で。」と聞いて、答えが「答え」と合っているか比べる。
whoamiわたしは誰？

何をするいまログインしている自分のユーザー名を表示する（who am I＝わたしは誰）。

例 s1234567
答え：何段目？
1段目（あなた）。ただし、その名前を覚えているのは3段目のカーネルです。whoami はカーネルに「このプログラムは誰のものですか」と聞いて、表示しているだけです。
echo $SHELLウェイターの名前

何をするecho は後ろに書いたものを表示するコマンド。$SHELL は「あなたが使っているシェル（コマンドを受け付けるプログラム）の場所」が入った変数。合わせて、使っているシェルを表示します。

例 /bin/bash
答え：何段目？
2段目（コマンドとシェル）。いま $ を出してあなたの入力を待っているのが、この bash というプログラムです。レストランでいえば、注文を受けるウェイターです。
psいま動いているもの

何をするこの端末でいま動いているプログラム（プロセス）の一覧を表示する（process status）。

例 PID TTY TIME CMD 4321 pts/0 00:00:00 bash 4400 pts/0 00:00:00 ps
答え：何段目？
2段目。bash（シェル）と、ps 自身が見えます。コマンドを打つと、そのたびに2段目にプログラムが1つ生まれて、終わると消えます。この一覧を持っているのも、3段目のカーネルです。
uname -s厨房の名前

何をするuname は「動いているシステムの名前（unix name）」を表示するコマンド。-s は「カーネルの名前（system）だけ」という指定（オプション）。

例 Linux
答え：何段目？
3段目（カーネル）。ここで初めて、「Linux」という名前が3段目の名前だと分かります。
uname -r厨房の名札

何をする-r は「カーネルのバージョン（release）だけ」という指定。今日いちばん会ってほしいコマンドです。

例 6.8.0-45-generic（数字は教室のコンピューターによって違います）
答え：何段目？
3段目（カーネル）。この数字は、あなたの命令を実際に処理しているカーネルの版です。1991年にリーナスが公開したのは 0.01 版でした。そこから世界中の人の手で直され続けて、今この番号になっています。
cat /etc/os-releaseお店の名前

何をするcat はファイルの中身を表示するコマンド。/etc/os-release は「このコンピューターに入っている Linux の種類」が書かれたファイル。

例 PRETTY_NAME="Ubuntu 24.04.1 LTS"NAME="Ubuntu"（以下、数行続く）
答え：何段目？
2段目と3段目のセット全体。これが「ディストリビューション」の名前です（Linux標準教科書 1.2.2）。uname -s の Linux（厨房）と、ここに出る Ubuntu などの名前（お店のブランド）は、別のものです。
which lsウェイターはどこにいる

何をするwhich は、コマンドの実体のファイルがどこにあるかを表示する（Linux標準教科書 5.10）。

例 /usr/bin/ls
答え：何段目？
2段目。ls は特別なものではなく、ディスクに置かれた普通のファイル（プログラム）です。第2・3週目にあなたが gcc で作ったプログラムと、同じ種類のものです。
nprocコンロは何口

何をするこのコンピューターで使える CPU（計算する部品）の数を表示する（number of processors）。

例 8
答え：何段目？
4段目（ハードウェア）。でも nproc は CPU に直接さわったわけではありません。カーネルに「CPU はいくつ？」と聞いて、答えを表示しただけです。
free -h食材庫の広さ

何をするメモリ（作業台）の大きさと、空いている量を表示する。-h は「人間が読みやすい単位（G や M）で」という指定（human-readable）。

例 total used free ...Mem: 15Gi 3.1Gi 9.8Gi ...
答え：何段目？
4段目（ハードウェア）。これも、カーネルに聞いて表示しています。

課題1で気づいてほしいこと

4段目（ハードウェア）のことを知りたいときも、コマンドはカーネルに聞いていた。2段目から4段目に、直通の道はありません。第2週目の1文「すべての出入りは、カーネルという1点を通っている」は、こういう意味でした。

課題2　AI証言カードを確かめる

必須下の3枚は、先生が Copilot の答え方をまねて作った「証言カード」です。3枚のうち1枚に、もっともらしい間違いが1か所だけ入っています。コマンドを打って、どれが間違いかを見つけてください。

自分の組を選ぶ

学籍番号の末尾が奇数の人は A 組、偶数の人は B 組です。隣の人と組が違っていても、そのまま自分の組をやってください（答えを写せないようにしてあります）。

やり方（1枚あたり5分）

  1. カードの「質問」と「AI の答え」を読む。
  2. 15秒で予想する。○（正しい）か ×（間違い）か。
  3. 確かめるコマンドを自分で考えて打つ。思いつかなければ「確かめ方のヒント」を開く。
  4. 結果を見て、カードの下の ○ ／ × を押す（この印は自分用です。保存はされません）。
A-1カーネルの版
質問uname -r を打つと、何が分かりますか。
AI の答え動いている Linux カーネルのバージョンが分かります。たとえば 6.8.0-45-generic のような文字列が表示されます。ディストリビューションの名前（Ubuntu など）は表示されません。それを知りたいときは cat /etc/os-release を使います。
押すと色が付きます（保存はされません）
確かめ方のヒント
uname -r と cat /etc/os-release を両方打って、出てきたものを見比べる。課題1でやったことです。
A-2パイプのしくみ
質問パイプ | は、どうやって前のコマンドの出力を後ろのコマンドに渡していますか。
AI の答えパイプは、前のコマンドの出力をいったん今いるディレクトリに一時ファイルとして保存し、後ろのコマンドがそのファイルを読むしくみです。そのため、ls | wc -l を実行するたびに、今いるディレクトリのファイルが1つずつ増えていきます。
押すと色が付きます（保存はされません）
確かめ方のヒント
本当にファイルが増えるなら、数えれば分かるはずです。ls | wc -l を3回続けて打ち、出てくる数が増えていくか見てください。ls -a（隠しファイルも表示）で、見慣れないファイルが増えていないかも見てください。
A-3行を数える
質問wc -l numbers.txt は何を表示しますか。
AI の答えwc は word count の略で、-l を付けると行の数を数えます。numbers.txt が 200 行のファイルなら、200 numbers.txt のように、行数とファイル名が表示されます。
押すと色が付きます（保存はされません）
確かめ方のヒント
そのまま wc -l numbers.txt を打つ。本当に 200 行かどうかは、tail -3 numbers.txt（最後の3行を表示）で最後の数字を見るとよい。
B-1コマンドの居場所
質問which ls は何をするコマンドですか。
AI の答えls という名前で実行されるプログラムの実体が、ディスクのどこにあるかを表示します。多くの Linux では /usr/bin/ls と表示されます。ls も、普通のファイルとしてディスクに置かれたプログラムだということです。
押すと色が付きます（保存はされません）
確かめ方のヒント
which ls を打つ。出てきた場所に本当にファイルがあるかは、ls -l /usr/bin/ls（出てきた場所を ls -l する）で確かめられる。
B-2成功か失敗か
質問echo $? を打つと、何が分かりますか。
AI の答え$? には、直前のコマンドがうまくいったかどうかを表す数字が入っています。成功したときは 1、失敗したときは 0 です。コンピューターでは 1 が「はい（真）」、0 が「いいえ（偽）」を表すことが多いので、それと同じ考え方です。
押すと色が付きます（保存はされません）
確かめ方のヒント
必ず成功するコマンドと必ず失敗するコマンドを用意して、それぞれの直後に echo $? を打つ。たとえば ls（成功）と、ls nofile（存在しないファイル名を渡すので失敗）。
B-3隠れているファイル
質問ls -a の -a は何をするオプションですか。
AI の答え-a は all の略で、名前が .（ドット）で始まる隠しファイルも含めて、すべて表示します。ホームディレクトリで試すと、.bashrc などの設定ファイルが見えるはずです（Linux標準教科書 5.1.8）。
押すと色が付きます（保存はされません）
確かめ方のヒント
ls ~ と ls -a ~ を両方打って、増えたものを見比べる（~ はホームディレクトリ）。
